차량 Test Case로부터 **규칙을 준수하는 변수명(variable name)** 을 자동 생성하기 위한 **LLM 파이프라인**입니다.  
사양서(도메인 문서) 기반 **DAPT → 테스트케이스 기반 SFT → RAG로 동적 예시 주입** 흐름으로 성능을 고도화합니다.

---

## 1) 프로젝트 개요

### 목표
- 차량 제어기(Test Case) 문맥에서 **규칙 기반 네이밍 컨벤션**을 만족하는 변수명을 자동 생성
- 도메인 문서/사양서 지식을 모델에 주입하고(DAPT), 테스트케이스로 작업 적합성을 높인 뒤(SFT),  
  실행 시 RAG로 관련 예시를 검색·주입하여 결과 품질을 안정화

### 파이프라인 요약
- **DAPT (Domain-Adaptive Pre-Training)**: 사양서/도메인 문서로 모델을 “도메인에 적응”시키는 추가 사전학습  
  - 본 프로젝트의 DAPT는 **CausalLM(다음 토큰 예측)** 방식으로 학습합니다. 문서를 토큰으로 이어 붙인 뒤 **고정 길이(block_size, 예: 4096 토큰)** 로 나누고, 각 구간에서 **앞 토큰을 보고 뒤 토큰을 순차 예측**하도록 학습해 도메인 표현을 강화합니다.
- **SFT (Supervised Fine-Tuning)**: 테스트케이스 입력→정답 변수명 형태로 지도학습하여 “과제 정합성” 강화  
  - 테스트케이스를 **(입력: 요구사항/조건/신호 정보 등) → (출력: 규칙을 만족하는 변수명)** 쌍으로 학습합니다. 도메인 지식뿐 아니라 **과제 형식(입출력 패턴)과 네이밍 규칙 준수**를 직접 최적화합니다.
- **RAG (Retrieval-Augmented Generation)**: 실행 시 유사 테스트케이스 예시를 검색해 프롬프트에 주입(동적 few-shot)  
  - 추론 시 입력 테스트케이스를 임베딩으로 변환해 벡터DB에서 **유사한 테스트케이스 입력**를 검색하고, 상위 K(=5)개를 프롬프트에 **few-shot 예시로 동적 삽입**합니다. 이를 통해 **희귀 규칙/예외 케이스**에서도 일관된 변수명 생성을 유도합니다.
